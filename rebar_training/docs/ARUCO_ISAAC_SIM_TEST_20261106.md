# ArUco 腕部相机 Isaac Sim 实测（2026-11-06）

本轮在 133 的现有 Isaac Sim / PhysX / RTX Camera 环境实际运行七组有界探针。**图像检测链路可以工作，但自动底盘校正未通过，尚未进入钢筋传递。** 全部成功和失败记录均保留，没有将进程 exit0 当作物理任务成功。Cosmos 完全未使用；策略和 optimizer 仅核对文件 SHA，未加载、修改或训练。

## 范围

使用原机器人、轮组和腕部相机资产，在独立场景中放置程序生成的真实 ArUco 黑白网格几何，由 RTX 渲染 RGB，再转 Mono8 交给 OpenCV 检测。没有把二维标记图叠加到相机画面，没有给检测器输入语义标签、深度或标记真值。机器人 link FK、固定 optical 外参与相机 K 属于允许的输入；场景真值另存用于评估。

这是**空载底盘与独立标记板的感知/局部校正探针**。标记板尚未安装到原测试机 CAD，虚拟夹具参考系由场景构造。没有验证带杆运输、碰撞可达性、三台机器身份绑定、原 MissionFlow 或完整钢筋上料。原正式64/64、旧演示1/1、新布局物理3/6的统计保持不变。

每组都有新输出目录、实际执行源码快照、命令和启动前 GPU 清单。前一组自然退出且 GPU 空闲后才启动下一组；不恢复或重派任何旧验收作业。运行均有步数和外层时限，没有安装或修改共享 SDK。七组结束后本任务 GPU 进程已退出。

这里40张是同一探针时序中的图像，不能当作40个独立布局或成功回合。表中“夹具点位置误差”是 `base_from_fixture` 的平移误差，不能与 `fixture_from_base` 的基座位置误差混为一谈。

实际安装需保证标记整个外黑框与白边在观察和校正过程中都可见。只在起始画面能识别不够，04的最后一帧提供了实际反例。

## 误差与同步复核

07中两帧的实际底盘位置仅变化0.01184mm，但估计位置变化3.39766mm；位置估计误差分别约13.396mm和10.028mm。夹具点的位置误差仍只有约0.5mm，方向误差约0.6°。对带有较长平移量的刚体变换求逆时，方向误差会放大为基座位置误差，这说明“小的夹具点位置误差”不能单独证明底盘定位精度。

记录的机器人 FK + 固定外参计算出的相机位姿，与 Camera 返回的位姿元数据相差约0.00002mm、0.000013°。该记录未显示明显的坐标变换方向错误；这项检查本身不独立证明 RTX 图像的真实曝光/缓存时间、角点系统偏差或内参像素约定完全正确。

没有放宽200ms/5ms、1px重投影、3mm/0.5°稳定性等门限来换取成功。03/05/06/07未获得启动轮组的资格；04的失败发生在实际轮组运动后。初始40mm/0.03rad偏差是试验开始前的一次显式重置，校正期间没有直接写机器人位姿。

## 平面约束：只做了真实图像离线排查，尚未仿真通过

新增实验类 `PlanarWristBoardEstimator`，显式假设底盘水平、夹具相对地面高度已知，只从图像解平面X/Y/偏航；保留原六维结果，并标明额外先验。高度固定于初始扰动之前的场景测量，没有把当前真实底盘X/Y/偏航输入解算器。

在07保存的两张原图、原K、原FK上离线复算，两次优化均收敛，但重投影RMS分别为1.232703px和1.074563px，仍超过原1px门限。因此**没有启动该变体的闭环仿真**。合成图单元测试通过不能覆盖这两张真实RTX图的拒收结果；不能把额外约束或平滑当作已解决定位问题。

下一步应先采集具有姿态/位置变化和独立留出帧的标定板渲染数据，核验相机内参的像素约定、角点偏差和时间链，再验证水平/高度先验的误差与适用条件。现场部署还需要真实手眼、标记到夹具的测量和独立量具验收。当前不接入自动传递。
