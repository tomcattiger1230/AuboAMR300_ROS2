# 车载钢筋送入测试机前的逆解不稳定（2026-09-26）

## 当前结论

车载第 1 槽重新取筋、抬升、竖直化和移动到测试机侧方暂存位均已在
Ubuntu `192.168.0.103` 的 Isaac Sim 中通过。连续运行随后在
`04_insert.py` 的 `onboard_preposition` 停下，错误为
`no IK solution for the joint fallback`。此时钢筋仍由机器人保持，测试机
抱爪未闭合；**尚未完成从初始场景到最终测试位置的一次无中断运行**。

一次断点续跑从相同的侧方暂存位成功送到了夹持线：钢筋中心
`(6.004, 3.901, 1.498)` m、轴线 Z 分量约 `0.99999`，机器人仍保持钢筋。
这证明目标和后续短距离插入路径在至少一种规划结果下可达，但不能据此认定
当前自动流程可靠。

## 已观察到的逆解分支

预插入目标为钢筋 TCP 世界坐标 `(6.0, 3.62, 1.50)` m，姿态由
`insert_quat` 给定。当前机械臂关节约为
`(6.0815, -0.4390, 0.9037, 1.3409, -1.3688, 0.0000)` rad
（依次为 shoulder、upperArm、foreArm、wrist1、wrist2、wrist3）。
该目标换算到当前底盘坐标约 `(-0.5667, 0.0029, 1.5000)` m。

KDL `/compute_ik` 对不同种子给出不同等效关节分支。当前实现只接受
`shoulder ∈ (2,4)`、`|wrist2| ∈ (1,4)`、`upperArm < 0`、
`foreArm < 0` 的分支，以避开此前在物理仿真中挤动底盘的短路径。
成功的断点续跑拿到了目标关节约
`(3.377, -0.045, -1.229, -1.184, -3.377, 0)` rad，
碰撞检查通过，规划轨迹 135 点，并执行成功。

连续运行即使增加种子 `(-2.8, 1.0, 1.1, 0.1, 2.8, 0)`，
本次 KDL 仍只返回其它分支，筛选后候选数为 0。
在停下的同一状态单独探测，近似关节目标
`(3.377, -0.045, -1.229, -1.184, -3.377, 0)` 的 FK 与请求位置
在毫米量级内，且一次碰撞检查关节规划成功（87 点）；另一个邻近目标
`(3.379, -0.050, -1.234, -1.183, -3.379, 0)` 的规划返回
`99999`，说明相近关节目标的可规划性也会变化。这些是诊断探针结果，
**固定关节目标尚未加入正式流程或做连续回归验证**。

此前另一轮连续运行在同一节点失败：
[失败报告](test/results/rebar_onboard_fresh_03_insert.json)。随后从现场姿态
重启 `04_insert.py`，得到
[成功报告](test/results/rebar_onboard_fresh_03_insert_retry.json)。
其中预插入分支为
`(3.377, -0.045, -1.229, -1.184, -3.377, 0)` rad，
碰撞检查轨迹 135 点；最终钢筋位置通过检查。

## 本次保留的代码改动与下一步

- `pickup_onboard.py` 入口停靠容差调整为 0.05 m、0.08 rad。原因是停车锁
  创建后曾出现约 3° 偏航，旧 0.04 rad 阈值在安全取筋前拒绝。插入节点
  仍独立重新校正并检查底盘。
- `test_rebar_tester_load.py` 为 `onboard_preposition` 增加一个 IK 种子。
  它使一次断点续跑成功，但连续回归仍失败，因此只视为局部改进。

恢复开发时应先在当前侧方暂存位复现，并记录**每个 IK 种子的返回码、
关节解及过滤原因**。然后尝试多个经 FK 校验的关节候选、碰撞检查和
轨迹执行，或改用稳定的分段侧向接近；需保留底盘安全偏差检查和钢筋
到位验证。最后从新场景连续运行四段，确认无需重启 `04_insert.py`。
